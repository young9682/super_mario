- 单文件 HTML5 Canvas 游戏，双击即玩；4 关（1-1 地面 / 1-2 地下 / 1-3 天空 / 1-4 城堡+库巴），8192 行左右含像素素材、关卡数据、物理、音效。
- 无浏览器可用，改用自研迷你 Canvas（`_render.js`，纯 Node + zlib 手写 PNG 编码）把游戏画面导出 PNG 目视检查；`_harness.js` 桩化 DOM 跑逻辑回归，`_bot.js` 机器人自动试跑 4 关，`_validate.js` 校验关卡几何（沟壑宽度/台阶高差/敌人落脚点），`_ground.js` 校验敌人精灵下沿是否贴合站立面。
- 关键约定：敌人精灵绘制统一用 `y - 2` 偏移，因此**精灵总行数 = 碰撞盒高度 + 2，且首行留空 1 行**，可见内容下沿必须落在碰撞盒最后一行，否则敌人会"悬空"。栗子怪 14→16 行，乌龟 22→24 行，龟壳 14→16 行。
- 修复记录：绿色乌龟悬空 —— 精灵只有 16px 高而碰撞盒 22px，脚底离地 9px；两帧高度还不一致（16/19）会上下抖。重画成 24 行（头 8 + 壳 9 + 腿脚 6），并顺手把栗子怪也下调 1px 贴地。
- 修复记录：踩扁敌人后仍会受伤。根因是 `stompEnemy` 只改 `state="squash"` 而**没动碰撞盒**（栗子怪 h 仍是 14，尸体还占满原身位 34 帧），且 `playerEnemyCollisions` 只跳过 `dead/flip`，没跳过 `squash`，玩家落回原地就判定受伤。修法：① `e.h = 6; e.y += 8`（底边不动）；② 玩家碰撞循环加 `|| e.state === "squash"` 跳过尸体；③ 火球循环同样跳过；④ `drawEnemies` 里尸体改为按碰撞盒底边对齐绘制 `sy + e.h - SPR.goombaFlat.r.height`，保证压低盒子后画面位置不变。
- 新增回归脚本 `_stomp.js`（可直接复现该 bug：把修复撤掉即 FAIL 2 项），另用 PIL 对截图做 NEAREST 放大裁切做目视对照。
- 修复记录：吃蘑菇变大后受伤，"又变大了"。根因在蹲下判定 —— `var wantCrouch = isBig() && ctrl && KEY.down && ...`，`KEY.down` 是 0/1 数字，`true && 0` 得数字 `0` 而非 `false`，而 `0 !== false` 恒为真，导致 `else { player.h = 30 }` 在"根本没蹲下"时也会执行；大马里奥静止时就已把 `player.crouch` 写成 `0`，于是受伤变小（h=15）后的下一帧被无条件顶回 h=30 → 又变回大 Mario。修法：① `!!(...)` 归一布尔；② 恢复站姿的分支加 `player.h === 16` 前置条件；③ `hurtPlayer`/`growPlayer` 改为**以底边为基准**切换身高并清 `crouch`（蹲着受伤不再穿地/被顶回）；④ 顺便补上原作那种"大小体型闪烁"过渡（`Math.floor(transform/4)%2`），并让动画收在正确姿势上。
